Stop loading skills into one agent.

The current workflow stacks every skill into a shared session: context bloats, model styles clash, runs drift. Skill Cell makes the skill the place, not the payload.

Today: skills into agent

  • Skill loads into a shared session
  • One context holds everything
  • Prompt-level behavior, drifts run to run
  • Personality clash across stacked skills
  • User chains steps by hand

Skill Cell: agent into cell

  • The skill is a workspace; the agent travels to it
  • Each cell holds only its own scope
  • Adapter plus pinned decode, deterministic
  • One adapter per cell, no cross-talk
  • Declarative DAG, reconciled by an orchestrator

Anatomy of a cell

A cell is a repo plus a manifest. It declares everything one skill needs to run end to end, and nothing outside its scope is reachable from inside it.

contract

Typed in, typed out, gated

Declared inputs and output artifacts, plus an eval gate that must pass before the cell reports done.

tools

Exact allowlist

Only the tools the cell names are reachable.

lsp

Servers in-cell

Symbol-accurate editing provisioned per cell.

loop

Plan, act, verify

Seven stages with an iteration cap and stop boundary.

runtime

Local or container

Git worktree, or an OCI image from a devcontainer spec. Same manifest.

model

A pinned base plus an optional LoRA adapter

Temperature zero, fixed seed, hashed weights. The backend is transformed into the skill instead of prompted with it, so runs are reproducible and free of cross-skill personality clash.

Three model planes, one interface

Keys come from the environment, never the manifest. A cell picks its plane; the agent adopts it on entry and leaks nothing on exit.

Frontier
ANTHROPIC_API_KEY
Hosted frontier model. Reach for it when no adapter exists yet; the cell still gets determinism from its contract and eval gate.
System-native
local endpoint
A model served on this machine over MLX or Ollama. No key required, nothing leaves the box.
BYOK
SKILLCELL_BYOK_KEY
Bring your own key for any OpenAI-compatible provider and base URL.
The differentiator. Everyone containerizes the runtime. Skill Cell is the layer that pins the skill itself to its own adapter, so behavior is deterministic and reusable, not just sandboxed.

Chain cells like a control plane

A Chain is a DAG of cells with typed artifact edges. The orchestrator provisions each cell, dispatches a subagent in, and passes artifacts on only after the eval gate clears. Local mode now, Kubernetes mode later, same manifests.

Roadmap

Local runner shipped first. Every later phase reuses the same manifest so nothing is rewritten to graduate to a cluster.

0

Local cell runner

Manifest, seven-stage loop, eval gate, three model planes. TDD'd, security-scanned, packaged.

1

Containerized cells

Devcontainer build; a cell passes identically local and in a container.

2

Adapter plane

Trace capture, LoRA training, adapter registry, adoption on dispatch.

3

Orchestrator and chains

Reconciler in Go, DAG scheduling, retry and fallback policy.

4

Kube mode

Manifests as real CRDs, cells as jobs, multi-LoRA serving at scale.
